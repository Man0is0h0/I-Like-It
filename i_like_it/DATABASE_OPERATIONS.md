# Database Operations: iLikeIt App

This document outlines all the database reads and writes performed by the app, split between the **Local Offline Database (SQLite)** and the **Remote Cloud Database (Supabase)**.

## 1. Local Database Operations (SQLite)
The app uses `sqflite` to manage local state. The exact SQL queries are generated by the `sqflite` package or run directly using `db.rawQuery` and `db.execute`.

### Folders
* **Get All Folders:** Retrieves all non-deleted folders along with a count of their non-deleted links.
  ```sql
  SELECT f.*, COUNT(l.id) as item_count 
  FROM folders f 
  LEFT JOIN links l ON f.id = l.folder_id AND l.is_deleted = 0 
  WHERE f.is_deleted = 0 
  GROUP BY f.id 
  ORDER BY f.created_at DESC
  ```
* **Insert Folder:** Creates a new folder.
  ```sql
  INSERT INTO folders (name, created_at, icon, updated_at, is_deleted) 
  VALUES (?, ?, ?, ?, 0)
  ```
* **Update Folder:** Updates a folder's properties.
  ```sql
  UPDATE folders SET name = ?, icon = ?, updated_at = ? WHERE id = ?
  ```
* **Delete Folder (Soft Delete):** Marks the folder and all its links as deleted.
  ```sql
  UPDATE links SET is_deleted = 1, updated_at = ? WHERE folder_id = ?
  UPDATE folders SET is_deleted = 1, updated_at = ? WHERE id = ?
  ```
* **Update System Category (AI Classification):**
  ```sql
  UPDATE folders SET system_category = ?, updated_at = ? WHERE id = ?
  ```

### Links
* **Get Links by Folder:** Retrieves all non-deleted links inside a specific folder.
  ```sql
  SELECT * FROM links WHERE folder_id = ? AND is_deleted = 0 ORDER BY created_at DESC
  ```
* **Get Recent Links:** Retrieves the most recently added links (limit 3).
  ```sql
  SELECT * FROM links WHERE is_deleted = 0 ORDER BY created_at DESC LIMIT 3
  ```
* **Get All Links:** Retrieves all non-deleted links across all folders.
  ```sql
  SELECT * FROM links WHERE is_deleted = 0 ORDER BY created_at DESC
  ```
* **Insert Link:**
  ```sql
  INSERT INTO links (folder_id, url, title, domain, image_url, notes, created_at, updated_at, is_deleted) 
  VALUES (?, ?, ?, ?, ?, ?, ?, ?, 0)
  ```
* **Update Link:**
  ```sql
  UPDATE links SET url = ?, title = ?, domain = ?, image_url = ?, notes = ?, updated_at = ? WHERE id = ?
  ```
* **Delete Link (Soft Delete):**
  ```sql
  UPDATE links SET is_deleted = 1, updated_at = ? WHERE id = ?
  ```

### Search
* **Search Folders & Links:**
  ```sql
  SELECT * FROM folders WHERE name LIKE '%{query}%' AND is_deleted = 0 ORDER BY created_at DESC
  SELECT * FROM links WHERE (title LIKE '%{query}%' OR url LIKE '%{query}%' OR notes LIKE '%{query}%') AND is_deleted = 0 ORDER BY created_at DESC
  ```

### Local Sync Helpers
* **Get Unsynced Folders:**
  ```sql
  SELECT * FROM folders WHERE cloud_id IS NULL OR updated_at > IFNULL(synced_at, "")
  ```
* **Get Unsynced Links:**
  ```sql
  SELECT * FROM links WHERE cloud_id IS NULL OR updated_at > IFNULL(synced_at, "")
  ```
* **Check if Folder/Link exists from Cloud:**
  ```sql
  SELECT * FROM folders WHERE cloud_id = ?
  SELECT * FROM links WHERE cloud_id = ?
  ```

## 2. Remote Cloud Database Operations (Supabase)
The app uses the `supabase_flutter` SDK, which converts method calls into REST API requests (using PostgREST). Below are the exact Supabase SDK queries used in `RemoteDataSource`.

### Syncing Folders
* **Push (Upsert) Folder:**
  ```dart
  _client.from('folders').upsert({
    'user_id': userId,
    'name': name,
    'icon': icon,
    'is_deleted': is_deleted,
    'updated_at': updated_at,
    'system_category': system_category,
    'id': cloud_id (if exists)
  }).select().single();
  ```
* **Pull New Folders:** Retrieves folders updated since `lastSyncTime`.
  ```dart
  _client.from('folders')
      .select()
      .eq('user_id', userId)
      .gt('updated_at', lastSyncTime)
      .order('updated_at');
  ```

### Syncing Links
* **Push (Upsert) Link:**
  ```dart
  _client.from('links').upsert({
    'user_id': userId,
    'folder_id': cloudFolderId,
    'url': url,
    'title': title,
    'domain': domain,
    'image_url': image_url,
    'notes': notes,
    'is_deleted': is_deleted,
    'updated_at': updated_at,
    'id': cloud_id (if exists)
  }).select().single();
  ```
* **Pull New Links:** Retrieves links updated since `lastSyncTime`.
  ```dart
  _client.from('links')
      .select()
      .eq('user_id', userId)
      .gt('updated_at', lastSyncTime)
      .order('updated_at');
  ```

### Users Table (`public.users`)
* **Create/Update User Record:**
  ```dart
  _client.from('users').upsert({
    'id': userId,
    'email': email,
    'last_seen_at': now
  });
  ```
* **Update Last Seen:**
  ```dart
  _client.from('users').update({'last_seen_at': now}).eq('id', userId);
  ```
* **Fetch User Role (Admin Checks):**
  ```dart
  _client.from('users').select('role').eq('id', userId).maybeSingle();
  ```
* **Fetch All Users (Admin):**
  ```dart
  _client.from('users').select().order('created_at', ascending: false);
  ```

### Supabase Remote Procedure Calls (RPC)
The app calls custom Postgres functions stored securely on your Supabase instance.
* **Check Email Exists:**
  ```dart
  _client.rpc('check_email_exists', params: {'email_to_check': email});
  ```
* **Request Recovery OTP:**
  ```dart
  _client.rpc('request_recovery_otp', params: {'p_email': email});
  ```
* **Verify Recovery OTP:**
  ```dart
  _client.rpc('verify_recovery_otp', params: {'p_email': email, 'p_code': code});
  ```

### Admin & Analytics
* **Count Total Users/Links/Folders:**
  ```dart
  _client.from('users').count(CountOption.exact);
  _client.from('links').count(CountOption.exact);
  _client.from('folders').count(CountOption.exact);
  ```
* **Fetch Folder Category Distribution:**
  ```dart
  _client.from('folders').select('system_category');
  ```
* **Batch Update AI Categories:**
  ```dart
  _client.from('folders').update({'system_category': category}).eq('id', id);
  ```

## 3. How the Sync Manager Works

The app operates on an **Offline-First** model, meaning all actions instantly write to the local SQLite database to provide a snappy experience. The `SyncManager` asynchronously synchronizes changes with the Supabase cloud when a network connection is available.

### Sync Triggers
* **App Launch:** Sync automatically runs when the app starts.
* **Network Restored:** `Connectivity().onConnectivityChanged` automatically triggers a sync when the device reconnects to Wi-Fi or Cellular.

### The 3-Step Sync Process

1. **Update Last Seen:**
   * Pings the cloud to update the `last_seen_at` timestamp for the current user.
   * **Supabase Query:**
     ```dart
     _client.from('users').update({'last_seen_at': now}).eq('id', userId)
     ```

2. **Push Local Changes to Cloud:**
   * Retrieves all **folders** and **links** from SQLite where `cloud_id IS NULL` (newly created offline) OR `updated_at > synced_at` (modified offline).
   * **SQLite Read Queries:**
     ```sql
     SELECT * FROM folders WHERE cloud_id IS NULL OR updated_at > IFNULL(synced_at, "")
     SELECT * FROM links WHERE cloud_id IS NULL OR updated_at > IFNULL(synced_at, "")
     ```
   * Iterates through these items and calls the Supabase `.upsert()` function to push the data.
   * **Supabase Upsert Queries:**
     ```dart
     _client.from('folders').upsert({...}).select().single();
     _client.from('links').upsert({...}).select().single();
     ```
   * If a record is pushed successfully, Supabase returns the cloud `id`. The `SyncManager` then updates the local SQLite record with the new `cloud_id` and sets `synced_at` to match `updated_at`.
   * **SQLite Update Queries:**
     ```sql
     UPDATE folders SET cloud_id = ?, synced_at = ? WHERE id = ?
     UPDATE links SET cloud_id = ?, synced_at = ? WHERE id = ?
     ```
   * *Note:* Deletions are "soft deletes", meaning `is_deleted` becomes `1` (or `true`). These are also pushed to the cloud.

3. **Pull Remote Changes to Local:**
   * Fetches the latest records from Supabase where `updated_at > lastSyncTime`.
   * **Supabase Pull Queries:**
     ```dart
     _client.from('folders').select().eq('user_id', userId).gt('updated_at', lastSyncTime).order('updated_at');
     _client.from('links').select().eq('user_id', userId).gt('updated_at', lastSyncTime).order('updated_at');
     ```
   * Compares the cloud records with the local records using the `cloud_id` via `upsertFolderFromCloud` and `upsertLinkFromCloud`.
   * **SQLite Check Existing Query:**
     ```sql
     SELECT * FROM folders WHERE cloud_id = ?
     ```
   * **SQLite Upsert Queries (If exists vs new):**
     ```sql
     UPDATE folders SET name = ?, icon = ?, updated_at = ?, is_deleted = ?, synced_at = ?, system_category = ? WHERE cloud_id = ?
     -- OR --
     INSERT INTO folders (cloud_id, name, icon, updated_at, created_at, is_deleted, synced_at, system_category) VALUES (?, ?, ?, ?, ?, ?, ?, ?)
     ```
   * *Relationship Mapping:* When pulling links, it looks up the local `folder_id` matching the incoming `cloud_folder_id` so the SQLite relationships remain perfectly intact.
     ```sql
     SELECT id FROM folders WHERE cloud_id = ?
     ```
